# Worldline card terminal / TIM API (#102) — invariants and gotchas

Design: odoo-erp issue 7598 (draft issuecomment-6618078139, ROZHODNUTÉ issuecomment-6618106435); lanes D1 (binding + session + logs, shipped 0.8.57), D2 (purchase two-phase + commit / rollback + reconcile), D3 (reversal / credit / activate / deactivate / balance / print_copy / LAN GET).

- **The SDK is licensed Worldline partner material — NEVER commit any SDK file, header, binary, jar or copied header text** (the repo is public MIT). On dev1 it lives at `~/vendor/worldline/` (`sdk/TimSdk/` unzipped from `TimSdk_26-09.zip`; headers `C/TimApi/Include/timapi/`, `Libraries/Windows/64bit/timapi.dll` + `timapi.def`, `Libraries/Unix/64bit/libtimapi.so.3.42.0-9115`, `Tools/EftSimulator/EftSimulator-3.34.0-9115.jar`; the design lane's C probe `eft-probe-from-design-lane/tim_probe.c` is the reference call order).
- **Loaded at runtime with `libloading`** (`tim/ffi.rs`, a hand-written subset): every symbol resolved at load (a missing one = load error). ABI from the headers: `ta_object_t` opaque pointer, a function that hands one out RETAINS it (release with `ta_object_release_if_valid`); `ta_e_result_code_t` int, ok = **1**; `ta_e_boolean_t` undefined 0 / true 1 / **false 2** (never pass 0 for false); OnFixIP = 1; no calling-convention macro. timapi.dll imports only system DLLs (ADVAPI32, CRYPT32, KERNEL32, msvcrt, USER32, WS2_32). A new FFI function: check its name in `timapi.def` and its signature + ownership in the header first.
- **Connect per use, never held**: `run_session` = create settings + terminal → connect → login → terminal id (checked against `terminal_tid`) → logout (only after a login) → disconnect (always after a connect) → dispose on drop. **`RECONNECT_GAP` 2 s** between two sessions on one terminal: the EftSimulator notices a disconnect ~0.5 s later and refuses a connect until then (`api_connect_fail_terminal`, measured 4.11.2026); a real terminal is checked on the ETU (lane V). No timer probe ever — the terminal takes ONE ECR connection and Codex still uses pjsnvs'.
- **D1 runs no card job**: `TimExecutor::check` refuses every `card.*` `unsupported` before journaling; `reconcile` answers `StillUnknown` (never "nothing ran" — a row could come from another executor). `test_executor = true` wins over `[client.pokladna.tim]` (WARN).
- **Status** (`terminal=`): `offline` (library not loaded / no till with a terminal / last session of a terminal failed), `busy`, `tim-ok`. A library that does not load is an ERROR + `offline`, never a start failure (printing keeps running); bad VALUES (`commit_timeout_s` outside 50..=300, integrator ID not a UUID, terminal_ip not IPv4, a terminal listed for two tills) refuse the start like any pokladna error, mirrored by the installer.
- **TIM logs**: `ta_logger_set_global_logger` registered ONCE per process (`Once`), the callback never unwinds into C (`catch_unwind`) and only appends to a mutex-guarded `DailyLog`. TIM 3.42 publishes up to **FINE** (level 4) — no FINEST records exist; every level is written. Past days gzipped through `<name>.gz.tmp` + rename, `.gz` older than 100 days deleted, at start and at each day change. `tim-settings.cfg` = our settings + the library's `ta_object_to_string` (its dump shows integrator ID, `auto_commit=false`, `commit_timeout=60`, connect timeout 30 s).
- **Tests**: unit tests over a fake `TimBackend` / `TimTerminal` (`tim/tests.rs`, CI). The real library + simulator only LOCALLY: start the simulator headless (`setsid nohup xvfb-run -a -s "-screen 0 1280x1024x24" ~/opt/jre17/bin/java -Djava.util.logging.config.file=eftsimulator-logging.properties -jar <jar>` from a dir holding its `Brands.xml` / `SimulatedCards.simcards`; it listens on `127.0.0.1:7784`, connect + login need no card click), then `DEVBRIDGE_TIM_LIBRARY=<libtimapi.so…> DEVBRIDGE_TIM_SIM_IP=127.0.0.1 cargo test -p devbridge-client --features tim-sim --test tim_sim -- --test-threads=1` (both env vars required — a missing one fails). CI never enables `tim-sim` until Worldline answers the licence question (design §7 Q4). Card actions (Tap / Accept) for D2 are XTEST clicks (`eft-probe-from-design-lane/xctl.py`).
- **Mutation**: `tim/ffi.rs`, `tim/native.rs` and the logger install / C callback are excluded (`.cargo/mutants.toml`) — they need the real library. Keep decisions in `tim/mod.rs` / `tim/logs.rs` so they stay mutated; log lines unconditional (a log-only `if` is a missed mutant).
- **NEVER** connect to a store's terminal, write a store config or enable `[client.pokladna.tim]` on a store before the owner approves the pilot.
