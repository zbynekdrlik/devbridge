# Worldline card terminal / TIM API (#102) — invariants and gotchas

Design: odoo-erp issue 7598 (draft issuecomment-6618078139, ROZHODNUTÉ issuecomment-6618106435); lanes D1 (binding + session + logs, shipped 0.8.57), D2 (purchase two-phase + commit / rollback + reconcile, 0.8.58), D3 (reversal / credit / activate / deactivate / balance / print_copy / safety balance / LAN GET, 0.8.59).

- **The SDK is licensed Worldline partner material — NEVER commit any SDK file, header, binary, jar or copied header text** (the repo is public MIT). On dev1 it lives at `~/vendor/worldline/` (`sdk/TimSdk/` unzipped from `TimSdk_26-09.zip`; headers `C/TimApi/Include/timapi/`, `Libraries/Windows/64bit/timapi.dll` + `timapi.def`, `Libraries/Unix/64bit/libtimapi.so.3.42.0-9115`, `Tools/EftSimulator/EftSimulator-3.34.0-9115.jar`; the design lane's C probe `eft-probe-from-design-lane/tim_probe.c` is the reference call order).
- **Loaded at runtime with `libloading`** (`tim/ffi.rs`, a hand-written subset): every symbol resolved at load (a missing one = load error). ABI from the headers: `ta_object_t` opaque pointer, a function that hands one out RETAINS it (release with `ta_object_release_if_valid`); `ta_e_result_code_t` int, ok = **1**; `ta_e_boolean_t` undefined 0 / true 1 / **false 2** (never pass 0 for false); OnFixIP = 1; no calling-convention macro. timapi.dll imports only system DLLs (ADVAPI32, CRYPT32, KERNEL32, msvcrt, USER32, WS2_32). A new FFI function: check its name in `timapi.def` and its signature + ownership in the header first.
- **Connect per use, never held**: `run_session` = create settings + terminal → connect → login → terminal id (checked against `terminal_tid`) → logout (only after a login) → disconnect (always after a connect) → dispose on drop. **`RECONNECT_GAP` 2 s** between two sessions on one terminal: the EftSimulator notices a disconnect ~0.5 s later and refuses a connect until then (`api_connect_fail_terminal`, measured 4.11.2026); a real terminal is checked on the ETU (lane V). No timer probe ever — the terminal takes ONE ECR connection and Codex still uses pjsnvs'.
- **D2 card jobs** (contract `docs/device-jobs-card.md`; `tim/card.rs` pure decisions, `tim/purchase.rs` the held session, `tim/jobs.rs` dispatch + reconcile, `journal_card.rs` table `card_payments`): `card.purchase` = ONE blocking session on the terminal queue that stays connected from the transaction until commit / rollback / `rollback_deadline_s` — **the simulator refuses `logout` while it waits for the commit (`request_pending`) and the disconnect then HANGS**, so never end a session with an authorisation pending. The generic journal row stays `executing` all that time (restart recovery unchanged); the card row (baseline `trans_seq`, amount, contact / authorised / ended times, the authorised result, `auth_ack`, person flag) + `device_contact_at` are written in ONE transaction BEFORE `ta_terminal_transaction`; `card_contact` false (already asked) = never a second transaction, `indeterminate`. `card.commit` / `card.rollback` run on `<ip>#settle` (NOT the terminal queue — they would wait behind the held purchase until the deadline) and only hand a `SettleRequest` to the holder (`holders` map, registered BEFORE the authorisation is journaled); no holder → the purchase's journal state answers. The `phase: "authorized"` ack (`AckRequest::Authorized`) is owed only while the row is `executing`; `Journal::card_events` wakes the acker (the executor writes it mid-execute); an ack refused (`too_late`) rolls back within `REFUSAL_POLL`. Odoo's names are binding: payload `card_job_id` (not `purchase_job_id`).
- **D3 jobs** (contract `docs/device-jobs-card.md` §8–§13; `tim/ops.rs` the one-session jobs + `with_session`, `tim/reports.rs` balance / shift / copy answers, `tim/safety.rs` the 23:50 tick, `journal_card_balance.rs` table `card_balances`): `card.credit` = `TwoPhase::Credit` through the SAME held session (`PurchaseRequest::kind`, `TimTerminal::transaction(kind, amount)`); settle jobs accept a purchase OR credit `card_job_id`. `card_payments.tx_type` (1/2/3, a D2 journal migrates to 1) is what the reconcile's `correlate` expects as the last transaction's type. `card.reversal` = `ta_terminal_transaction2(reversal, request)` with ONLY `transaction_data.trans_seq` (a hand-made request, no amount) — measured: the simulator asks for Accept, answers the ORIGINAL amount + its own next `trans_seq`, no commit, a normal logout; rc 67 answers an unknown / already reversed TransSeq → `period_closed` (Odoo then composes a credit) ONLY with a `done` balance of that terminal after this bridge sent the payment (`card_balance_since_payment`), else `unknown_reference` — review finding: 67 read as a closed period could refund twice; a TransSeq is reversed at most once (`card_payments.target_seq` + `card_other_reversal` under the session lock → `already_reversed` / `reversal_unresolved`, nothing sent); a reconciled failed reversal is `not_reversed`; the simulator does NOT model the period close on a balance (a reversal after a balance still works) — the real code after a balance is an ETU item (lane V). Its trans_seq is stored with `card_transacted` (no authorised ack). Activate / deactivate are idempotent on the terminal (SDK + measured) → their reconcile RUNS THEM AGAIN unless a later shift job of the till is journaled (`card_later_shift_job`); balance reconcile → a person; print_copy reconcile → `failed print_unknown`. `card.print_copy {card_job_id}` (DevBridge's proposed payload, Odoo has none yet) prints only when the terminal's LAST `trans_seq` is the named payment's (`ta_terminal_receipt_request(reprint)` returns the latest receipt only). Balance counters: a brand total's `amount_sum` is the NET signed sum (measured −0.70 for 2.40 − 2.40 − 0.70); `ta_counter_get_count` / `ta_total_get_count` write an `int`, `ta_counter_get_acq_id` an `int64`. Safety balance: `DeviceExecutor::background()` (spawned by `DeviceJobSource::run`, aborted with it) → `safety_loop` every 60 s → `safety_tick(now)` (testable with any clock) → per terminal `card_balance_ran(ip, local date)` false (checked again INSIDE the session, after the queue wait) → a `safety` row (partial UNIQUE index, so a restart after 23:50 never runs a second) committed right before the call (`safety_session`); a refusal in the purchase table (busy …) drops the row (`card_balance_forget`), a failed connect journals nothing — both retried next minute; shift / balance errors go through `op_error` (purchase table → `failed`, else `indeterminate`). Odoo has no channel for it (O2 not built) — journal + log only. LAN API: `GET /v1/card-jobs/{kasa_id}/{client_uuid}` reads `device_jobs` (`card_job_by_uuid`, newest TILL-submitted card job of the till — never the Odoo-composed commit / rollback / shift jobs) — POST of `card.*` stays 422.
- **Result codes** (measured on the simulator 4.11.2026): decline rc 82, Stop rc 53, no card ~60 s → the library cancels itself rc 2; a failed transaction becomes the terminal's last transaction WITHOUT a response / trans_seq (so a crash after a decline with an empty journal = baseline unknown = a person); a rolled-back one keeps its response (`outcome=2`); a fresh simulator answers info `transaction_type=0`. Only the listed refusal codes are "nothing charged" (`card::classify_transaction_error`) — every other rc is `indeterminate`. Restart reconcile waits `commit_timeout_s` + 10 s past the latest moment, then correlates by EXACTLY the journaled `trans_seq` (else `trans_seq` > baseline) AND amount AND no later card row on that terminal (`card_later_on_terminal` — the till's retry of the same amount would otherwise "prove" the old payment rolled back / charged, review finding) — else a person, never guessed. An unknown end releases the terminal with rollbacks (until ok or rc 68 nothing pending, at most the CommitTimeout) BEFORE the logout. `rollback_deadline_s` 45..=min(commit−5, 90): Odoo's 30–40 s clock starts at the ack, ours at the authorisation. Getters of response objects are BORROWED (not retained — never release them, `native::Borrowed`); the full PAN / `card_ref` are never read. `test_executor = true` wins over `[client.pokladna.tim]` (WARN).
- **Status** (`terminal=`): `offline` (library not loaded / no till with a terminal / last session of a terminal failed), `busy`, `tim-ok`. A library that does not load is an ERROR + `offline`, never a start failure (printing keeps running); bad VALUES (`commit_timeout_s` outside 50..=300, integrator ID not a UUID, terminal_ip not IPv4, a terminal listed for two tills) refuse the start like any pokladna error, mirrored by the installer.
- **TIM logs**: `ta_logger_set_global_logger` registered on every library load (the `TimLibrary` is `ManuallyDrop` — NEVER unloaded, its threads may still call us), the callback never unwinds into C (`catch_unwind`), only appends to a mutex-guarded `DailyLog` (record parameters appended as `params=[…]`). A day change opens the new file at once and gzips the past days on a thread of its own (`housekeep_logged`, serialised) — a TIM thread never waits for a gzip, and a housekeeping error is a WARN, never a lost record or a failed load. TIM 3.42 publishes up to **FINE** (level 4) — no FINEST records exist; every level is written. Past days gzipped through `<name>.gz.tmp` + rename, `.gz` older than 100 days deleted, at start and at each day change. `tim-settings.cfg` = our settings + the library's `ta_object_to_string` (its dump shows integrator ID, `auto_commit=false`, `commit_timeout=60`, connect timeout 30 s).
- **Tests**: unit tests over a fake `TimBackend` / `TimTerminal` (`tim/tests.rs`, CI). The real library + simulator only LOCALLY: start the simulator headless (`setsid nohup xvfb-run -a -s "-screen 0 1280x1024x24" ~/opt/jre17/bin/java -Djava.util.logging.config.file=eftsimulator-logging.properties -jar <jar>` from a dir holding its `Brands.xml` / `SimulatedCards.simcards`; it listens on `127.0.0.1:7784`, connect + login need no card click), then `DEVBRIDGE_TIM_LIBRARY=<libtimapi.so…> DEVBRIDGE_TIM_SIM_IP=127.0.0.1 cargo test -p devbridge-client --features tim-sim --test tim_sim` (both env vars required — a missing one fails; the tests take a static mutex, one simulator). CI only LINTS it (Clippy step with `--features tim-sim`). CI never enables `tim-sim` until Worldline answers the licence question (design §7 Q4). Card actions are XTEST clicks: `DEVBRIDGE_TIM_SIM_XCTL=<…/eft-probe-from-design-lane/xctl.py>` plus `DISPLAY` / `XAUTHORITY` of the simulator's Xvfb (`ls /tmp/xvfb-run.*`; `xvfb-run -n <display>` picks it) — buttons at Tap (725,607), Accept (551,744), Stop (731,744), Decline (499,776) as the window opens on 1280×1024. The kill test re-runs its own test binary as a child (`--exact`, env `DEVBRIDGE_TIM_SIM_CHILD_JOURNAL`) that exits 9 after the authorisation; the whole file takes ~3 min (the reconcile waits 71 s); `test_d3_jobs_on_the_simulator` (activate ×2, purchase + commit, print_copy, reversal, the same reversal again → rc 67, credit + commit, balance, deactivate) ~45 s.
- **POS-ID** = the plain till id (`3`), ROZHODNUTÉ #102 issuecomment-6632469305: the SDK documentation of `ta_terminal_set_pos_id` limits it to a number of at most six digits (EP2); a till with a terminal needs an id ≤ 999 999 (`startup_validation.rs` + `Get-DevBridgePokladnaKasyProblems`).
- **Mutation**: `tim/ffi.rs`, `tim/native.rs` and the logger install / C callback are excluded (`.cargo/mutants.toml`) — they need the real library. Keep decisions (also pure FFI helpers like `check` / `c_text`) in `tim/mod.rs` / `tim/logs.rs` so they stay mutated; log lines unconditional (a log-only `if` is a missed mutant).
- **NEVER** connect to a store's terminal, write a store config or enable `[client.pokladna.tim]` on a store before the owner approves the pilot.
