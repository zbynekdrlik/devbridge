# Installer PowerShell — gotchas (auto-loads on installer/ and deploy/*.ps1)

- **Production runs Windows PowerShell 5.1 (as SYSTEM), not pwsh 7.** CI runs the installer Pester suite on BOTH (`installer-tests` job: pwsh 7 step + `shell: powershell` 5.1 step, #69). A test that passes only on pwsh 7 is a prod bug.
- **Never read a config with `Get-Content -Raw` and write it back as UTF-8.** PS 5.1 reads BOM-less UTF-8 as the ANSI code page, so the write-back double-encodes non-ASCII bytes. Use `[System.IO.File]::ReadAllText($Path)` + `WriteAllText($Path, $text, (New-Object System.Text.UTF8Encoding($false)))` (both serial-bridge merges do this since 0.8.36).
- **post-install.ps1 = procedural body; its helpers live in the sibling `installer/DevBridgeInstallerLib.ps1` (#80).** post-install dot-sources `Join-Path $PSScriptRoot 'DevBridgeInstallerLib.ps1'` and exits 1 BEFORE any change if it is missing. A NEW helper goes into the lib (functions ONLY — no top-level statements — pure ASCII, PS 5.1 syntax; `installer/tests/post-install-lib.Tests.ps1` asserts all three plus the exact function list, so add the name there too). The lib is shipped by listing it in `crates/devbridge-app/tauri.conf.json` `bundle.resources` right next to post-install.ps1 (both land in `<InstallDir>\_up_\_up_\installer\`); a new sibling file needs the same.
- **install.ps1 still can NOT dot-source anything** (it runs via `irm|iex` — no file on disk, `$PSScriptRoot` empty). A helper needed in both install.ps1 and post-install is defined inline in install.ps1 AND in the lib, and a Pester test asserts the two AST extents are byte-identical (`ConvertFrom-DevBridgeSerialBridgesSpec`, `Get-DevBridgeMissingVcRuntimeDlls` in `vc-runtime.Tests.ps1`). Edit one → copy verbatim to the other.
- **`post-install.ps1 -ValidateOnly`** loads the lib, runs only the read-only pre-change validation and prints `VALIDATE-OK <n> functions`, then exits 0 — the `e2e-deploy-client` packaging gate (`deploy/e2e-installer-packaging-gate.ps1`) runs the INSTALLED copy under 5.1 as SYSTEM on pz-snv and asserts the production `config.toml` hash is unchanged. Anything you add BEFORE the `-ValidateOnly` exit block must stay read-only.
- **Running a script as a real child process in Pester** (both editions): `Start-Process -FilePath (Get-Process -Id $PID).Path -ArgumentList "-NoProfile -ExecutionPolicy Bypass -File `"$script`" …" -Wait -PassThru -NoNewWindow -RedirectStandardOutput $o -RedirectStandardError $e` — same edition as the test run, no `2>&1` NativeCommandError surprises on 5.1 (see `post-install-lib.Tests.ps1`). Do not put `<word>` in an `It` name: Pester 5 treats it as a data-driven template placeholder and prints it empty.
- **Dash-leading VALUES through `powershell.exe -File`:** forward them as ONE `-Name:value` argument (`-OdooXOffsetDots:-5`) — that is how `Get-DevBridgePostInstallArgs` passes `DEVBRIDGE_ODOO_X/Y_OFFSET_DOTS` (#95); the -File parser treats dash-leading arguments as parameter names, and the colon form binds unambiguously (smoked on pz-server 5.1 and pwsh 7). pwsh 7 hands `-X:false` to a `[string]` param as `False` (5.1 as `false`) — validate such values case-insensitively and lower-case them for TOML.
- **Array `Should -Be`**: compare `(@($x) -join ",") | Should -BeExactly "a,b"` — a piped array unrolls and is not a reliable element-wise compare.
- **PowerShell hashtables are case-INSENSITIVE**; Rust `HashMap` keys (client_id) are case-sensitive. Use `[System.Collections.Hashtable]::new([System.StringComparer]::Ordinal)` when mirroring Rust key semantics.
- **Smoke a PS change under real 5.1 before pushing:** pz-server has only Pester 3.4, so do not run the suite there. Push the commit to the wip ref, then on pz-server `Invoke-WebRequest https://raw.githubusercontent.com/zbynekdrlik/devbridge/<sha>/installer/DevBridgeInstallerLib.ps1` (plus `post-install.ps1` into the SAME dir to smoke `-ValidateOnly -Mode server -DataDir <temp>`), AST-extract the functions (dot-source `deploy/lib/Get-FunctionSourceFromScript.ps1` from the same sha — the one extractor shared by both Pester suites and the E2E client setup, #70), and run them on a COPY of the live config in `C:\Windows\Temp\<dir>`. Delete the dir afterwards and confirm the live `config.toml` SHA256 is unchanged.
- The dev-branch CI E2E deploy upgrades pz-snv's PRODUCTION install with the REAL install.ps1 + post-install (#93 step, config preserved) and restarts `DevBridgeService`, so pjsnvs runs the dev build right after a green dev CI.
- **Literal `\uXXXX` text gets turned into the real character by the editing tools** (Write / heredoc), which broke Pester expectations like `'"Spi\u0161sk\u00E1"'` (#90). After writing any TOML-escape test, check `LC_ALL=C grep -nP '[^\x00-\x7F]' <file>` and rebuild such literals with `chr(92)` in a python edit if needed. Non-ASCII test INPUT is built from `[char]0x0161` (test files must stay ASCII for PS 5.1).
- **Non-ASCII config values go into config.toml as TOML `\uXXXX` escapes** (`ConvertTo-DevBridgeTomlString`, #90) — post-install writes the file `-Encoding ASCII`.
- **A helper that returns a list with the unary comma (`return ,$problems`) must be ASSIGNED before `.Count`** (`$p = Get-X; $p.Count`). `@(Get-X).Count` wraps the returned (even empty) list as ONE element → 1 (#88 CI failure in `Get-DevBridgeClientConfigProblems`).
- **install.ps1's upgrade region is `Install-DevBridgePackage` (#93): service stop -> `Stop-DevBridgeTrayApps` -> unlock -> tray re-check (a user logging on meanwhile) -> NSIS -> hash check -> post-install inside ONE try/catch/finally: the catch runs `Restore-DevBridgeService` and rethrows, the finally restores too when the run is stopped without a catchable error (Ctrl+C).** A new failure branch in there must `throw`, never `Write-Error ...; Restore-DevBridgeService`: install.ps1 runs with `$ErrorActionPreference = "Stop"`, so `Write-Error` is terminating and the restore after it never runs (that left 6 stores without printing for ~5 h). `autoupdate.ps1`'s catch additionally runs `Start-DevBridgeServiceIfStopped`.
- **Windows PowerShell 5.1 + `$ErrorActionPreference = "Stop"`: a native command's stderr redirected with `2>$null` / `2>&1` is a TERMINATING error** (`query user` with nobody logged on writes "No User exists for *"). Let cmd.exe drop or merge it: `@(cmd.exe /c "query user 2>nul")`, `cmd.exe /c "taskkill ... 2>&1"`. A static Pester scan (`upgrade-restore.Tests.ps1`) fails on any other `2>$null` / `2>&1` line in `installer/*.ps1` and `deploy/*.ps1`. Unredirected (or `| Out-Host` on stdout only) the stderr passes through harmlessly.
- **Under 5.1 a lone `[pscustomobject]` has no `.Count`** (`$null -gt 0` is false): wrap in `@()` or return an `object[]` with the unary comma (`$a = @(); $a += ...; return ,$a`). Never return a `List[object]`: 5.1 throws `Argument types do not match` on `@($list)` (CI run 36558620346). That is why single-user store PCs never got their tray back after an upgrade (`ConvertFrom-DevBridgeQueryUserOutput`, #93).
- **Script-level Pester (#93, `installer/tests/upgrade-restore.Tests.ps1`):** run the REAL `install.ps1` / `autoupdate.ps1` body in process (`& $script`) with every external effect mocked. Pester only mocks commands that already exist, so AST-define the script's own helpers first; the mock then wins over the script's definition. Mock bodies run in the script's scope (`$script:` is THAT script's), so keep mock state in one `$global:` table removed in `AfterAll`. Clear every `DEVBRIDGE_*` env var around each run.
- **`DEVBRIDGE_INSTALLER_PATH`** makes install.ps1 install a local `DevBridge_<ver>_x64-setup.exe` (no release fetch/download/checksum; version from the file name; the file is never deleted) — the CI real-upgrade step uses it, and it is the offline install path.
- **Never throw `PipelineStoppedException` inside an in-process Pester test** (to simulate Ctrl+C): it stops Pester's own pipeline and the run ends silently mid-file with no summary. Simulate it in a child process of the same edition (see the Ctrl+C test in `upgrade-restore.Tests.ps1`).
- **Local Pester loop on dev1 (no local Windows):** `~/.local/pwsh74/pwsh` + Pester 5.7.1 run the mocked suites if you first define global stubs for the Windows-only `Get-/Start-/Stop-ScheduledTask`; tests that spawn `powershell.exe`, touch ACLs or `C:` paths only run in CI (`installer-tests`, pwsh 7 + 5.1) -- that job is the authority.
