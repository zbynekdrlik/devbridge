# CI pipeline — gotchas (auto-loads on workflows and devbridge-ui-util)

- **CI runs on `push` to dev/main only** — a PR has no own run; its checks are the dev push run of the same head SHA. Merging to main re-runs the whole pipeline (incl. E2E on pz-server/pz-snv and Stable Release, which publishes `v<version>` that the fleet auto-update installs).
- **The mutation jobs run with `RUSTFLAGS: ""` (job-level override, prep AND shards — the shared `mutants` cache needs identical flags).** Under the workflow-wide `-D warnings`, a whole-function replacement mutant (`replace f -> Option<String> with None`) left a parameter unused, the warning became a compile error, and cargo-mutants counted the mutant **unviable** (not caught, not missed) — 0.8.38: `3 mutants tested: 3 unviable`; #99: 184 of 327 unviable. Warnings stay enforced by Clippy/Build/Test. Still read the job's `N mutants tested: … unviable` line (or `mutants-out/unviable.txt`) — "passed" with mostly unviable mutants proves little.
- **The mutation gate is SHARDED with its own warm cache (#99).** `mutation-prep` compiles the `mutants` profile (`cargo test --profile mutants --workspace --all-targets --no-run`) and saves it under rust-cache key `mutants`; the `Mutation Testing (k/12)` shards (12 since #101, whose diff had ~350 mutants; 6 before) restore it (`save-if: false`) and run `--in-diff pr.diff --shard k/12`; `.cargo/mutants.toml` has `copy_target = true` so cargo-mutants' scratch copies start with those dependencies. Before: the Test job's `shared-key: test` cache never held the `mutants` profile and cargo-mutants copied an empty target/ → ~14 min cold compile before the first mutant, 325 mutants overran the 20-min cap. Never raise `timeout-minutes`; add shards or narrow scope.
- **Guards that the SQL already filters are invisible to integration tests** — a match guard like `JobState::Done if !self.acked` behind `WHERE acked = 0` survives `guard → true`; test the method on hand-built entries. A helper that only stamps time (`now()`) survives `-> String::new()/"xyzzy"` unless a test parses the stored timestamp. A `>=` against `Instant::now()` taken a moment later is an equivalent mutant (`>` behaves the same) — move the comparison into a pure fn and test the equal case.
- **Logging-only branches become MISSED mutants** (`if waited_ms > 0 { info! } else { debug! }`, `if !recovered.is_empty() { warn! }`): no test can observe them. Log unconditionally (one line with the value as a field) instead of branching on it (#90). A non-Windows stub whose body already equals the mutant (`-> None`) needs an `exclude_re` for exactly that mutant.
- **cargo-mutants runs ONLY the mutated crate's tests**: a decision in `devbridge-core` that only a server or client test exercises is MISSED (#101: `c == '"'` → `!=` in the core `[server.acme]` e-mail check, covered only by a server test). Test every decision in its own crate.
- **Every wait in a test must be bounded**: an unbounded `while cond { sleep }` turns each mutant that breaks `cond` into a 300 s TIMEOUT (counted "ok", but six of them cancelled a shard at its 20-min cap, #101). Poll with a deadline and panic, e.g. `FakeCa::wait_for_calls` in `devbridge-server/src/cert/tests.rs`.
- **`cargo test --workspace` stops at the first failing test binary** — a red lib test hides whether the integration tests (`tests/*.rs`) pass; read the next run too.
- **Pull a single job's log** with `gh api --allow-escape-sequences repos/zbynekdrlik/devbridge/actions/jobs/<job-id>/logs > file` (job ids from `gh run view <run> --json jobs`; without the flag gh prints NOTHING for logs with ANSI colours); `gh run view --log` mislabels job names and returns nothing while the run is still in progress.
- **`portos-live` (#100)** runs the `portos_live` tests behind `--features portos-live` (never compiled by Test / mutation; Clippy lints them in an extra step) against a real Portos installed by `deploy/ci-portos-inmemory.ps1`, and fails unless EXACTLY `PORTOS_LIVE_TESTS` passed — a new live test bumps that number in the same commit (8 since #101's LAN receipt case). It is in `tier1-pass` needs.
- **`ACME (Pebble)` (#101)** runs `crates/devbridge-server/tests/acme_pebble.rs` behind `--features acme-pebble` (never compiled by Test / mutation; Clippy lints it in an extra step) against pinned Pebble v2.10.1 + pebble-challtestsrv downloaded with SHA256 checks — the real ACME DNS-01 order of `cert/acme.rs`, which is therefore in `.cargo/mutants.toml` `exclude_re`. Pebble's own TLS cert names `localhost` (directory `https://localhost:14000/dir`, root `test/certs/pebble.minica.pem` from the same release); `PEBBLE_WFE_NONCEREJECT=0` (no random badNonce) and `PEBBLE_VA_NOSLEEP=1`. challtestsrv answers Pebble's TXT queries (`-dnsserver :8053`, Pebble started with `-dnsserver 127.0.0.1:8053`; management API `:8055`); the test's DNS provider writes there. It is in `tier1-pass` needs. Never point CI at Let's Encrypt.
- **`cargo mutants --in-diff` on Linux mutates `#[cfg(windows)]` code it never compiles** → every such mutant is "MISSED" (build ok, tests pass). Put Windows-only code in its own file and add that path to `.cargo/mutants.toml` `exclude_re` (e.g. `backend_windows_spooler_raw/platform_windows.rs`, #88); keep the pure decision helpers in the tested file so they stay mutated.
- **`git push` rejected with GH007 "would publish a private email"** (owner account setting, since 2026-09-26): commits must use `26905282+zbynekdrlik@users.noreply.github.com` (set as this checkout's `user.email`). Re-author unpushed commits with `git restore --source=<c> --staged --worktree -- . && git commit -C <c> --reset-author` per commit, never amend/rebase.
- **`windows-build` runs the `cfg(windows)` lib tests of `odoo_source::printer_status` only** (#97: release profile + the service build's RUSTFLAGS, so its deps are reused) and fails unless exactly the 3 Windows tests passed. A new `cfg(windows)` test elsewhere needs its module added to that step's filter AND count check — otherwise it never runs anywhere (the Test job is ubuntu).
- **An integration-test file nearing 1000 lines → a multi-file test target** `tests/<name>/main.rs` + sibling modules (one binary; shared fakes in a `fake.rs` with `pub` items and `pub` fields, each scenario module imports `super::fake::*` plus its own external `use`s) — separate `tests/*.rs` files sharing a `common` module would hit `dead_code` under `-D warnings` (#99).
- **CLI tools in CI come PREBUILT, never `cargo install` from crates.io** (`taiki-e/install-action` or `cargo binstall … --disable-strategies compile` with `GITHUB_TOKEN`): a source install resolves the tool's dependencies anew, so an upstream yank breaks it with no change on our side — 2026-10-13 every `zip` 8.x was yanked and `cargo install tauri-cli` (`zip = "^8"`) failed in macOS Build, which blocked Stable Release of 0.8.48 (`stable-release` needs `macos-build`).
- **The pjsnvs store line (pz-snv runner) is throttled to ~2–10 KB/s at night** (15.10. ~23:00Z–05:06Z, 16.10. ~22:30Z–06:10Z; VPN included, PC idle): `E2E Deploy Client` then dies before its first step on `actions/download-artifact` (codeload, HttpClient 100 s × 3). Infra, not code — probe from pz-snv (`mcpx.py win-pjsnvs-pokladna`, timed `Invoke-WebRequest` of the codeload zip), wait for recovery, then ONE `gh run rerun <id> --failed`.
- **Gates rot between tickets**: a new RustSec advisory (cargo audit + cargo deny both fail) or a new clippy lint on stable (1.99 `double_must_use` on every `#[async_trait]` trait method, async-trait ≤ 0.1.89) turns a clean branch red. Fix it in the same PR as a separate lock-file commit with `cargo update -p <crate>` (non-compiling, allowed under Tier 0). Clippy stops at the first failing crate, so after such a fix your own crate's lints run for the first time.
- **`windows-build` installs trunk with cargo-binstall**: without a token its GitHub release lookups hit the anonymous API limit (403), binstall then BUILT trunk from source, and an unlocked build broke on a new `cssparser` (`lightningcss` E0277 errors, #101 run 38796197031). The step passes `GITHUB_TOKEN: ${{ github.token }}` and `--locked`; a `lightningcss` / `cssparser` compile error in "Install trunk" is this, not your code. cargo-binstall itself comes prebuilt (`taiki-e/install-action`): compiled from source it took 9 of the job's 30 minutes on a cold rust cache (any Cargo.lock change) and the job was cancelled at the cap while saving its cache — check step times before touching `timeout-minutes`.
