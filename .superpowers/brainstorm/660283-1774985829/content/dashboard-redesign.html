DevBridge Dashboard Redesign

Pick the layout approach for the job list — the core of the dashboard

Current Problems

  • Job ID too prominent — full UUID shown large, timestamp tiny
  • Auto-collapse on refresh — 3s refresh resets expand state, unusable
  • No information hierarchy — everything same visual weight
  • Ugly layout — not matching modern 2026 dashboard standards
A

Timeline Feed (Recommended)

Each job is a card with large timestamp + ago on the left, status pill, document name. Audit events always visible below (no collapse). Job ID as tiny muted text at bottom. Like a social media feed — newest on top, scroll down for older.

Pro: No collapse/expand needed. Full audit always visible. No state lost on refresh.
Con: More vertical space per job. Need "Show more" for 50+ old jobs.

B

Compact Row + Sticky Expand

Compact one-line rows like current, but expand state persisted in URL hash so refresh doesn't collapse. Timestamp large on left, ID hidden until hover.

17:35:00 (53m ago) completed sample.pdf 4ae0d303 ▼
17:17:57 (1h ago) completed invoice.pdf 76dfa399 ▼

Pro: Compact — many jobs visible at once. Good for server with dozens of jobs.
Con: Still needs click to see audit. URL hash persistence adds complexity.

C

Hybrid: Last 3 Expanded, Rest Compact

Most recent 3 jobs show full timeline (like A). Older jobs collapse to single row (like B). Auto-expand for newest jobs means you always see what just happened without clicking.

Pro: Best of both — recent jobs have full detail, older jobs don't waste space.
Con: Two different visual treatments on same page.
